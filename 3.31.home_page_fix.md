# Implementation Plan: Merging Deals Tab into Home Tab (Discovery vs. Search Mode)

## Objective
Consolidate the "Deals" and "Home" tabs into a single, smart entry point to reduce bottom navigation clutter (from 6 icons down to 5) and improve the initial user experience by placing search functionality front and center immediately upon app load.

## Core Behavior
- **Default State (Discovery Mode):** When the user opens the app without active filters or search queries, the Home tab displays the standard carousels (`Deals Near Me`, `Use Again`, `Featured`). The `Sidebar` (Search Bar, Category Filters, Sort Control) resides pinned to the top of the view.
- **Active State (Search Mode):** The moment a user interacts with the Search Bar, selects a Category Filter, or alters the Sort order, the carousels are hidden. The view transitions to display the filtered `ListView` of deals, acting identically to the legacy "Deals" tab.

## Step-by-Step Implementation Guide

### 1. Refactor `App.jsx`
- **Routing Removal:** Remove the `activeTab === 'deals'` rendering block completely. 
- **Bottom Navigation Update:** Update `<BottomNav>` to only output 5 tabs (`home`, `map`, `faves`, `rewards`, `settings`). Delete the "deals" tag configuration.
- **Props Update for HomeTab:** Provide `HomeTab` with both the full deal structure (for computing discovery carousels) and the `useFilters` managed output.
  ```jsx
  <HomeTab
    deals={dealsWithUsage}
    filteredDeals={filteredDeals} // Provide the filtered subset for search mode
    usageLog={usageLog}
    userCoords={coords}
    onSelectDeal={handleSelectDeal}
    
    // Pass filter/sidebar props down
    searchQuery={searchQuery}
    onSearchChange={setSearchQuery}
    activeCategories={activeCategories}
    onCategoryToggle={toggleCategory}
    onClearFilters={clearFilters}
    sortBy={sortBy}
    setSortBy={handleSetSortBy}
    categoryCounts={categoryCounts}
    // ...other necessary props for the Sidebar components
  />
  ```

### 2. Update `HomeTab.jsx` component structure
- **Import Components:** Bring `Sidebar` (which encapsulates `SearchBar`, `FilterPanel`, `SortControl`) and `ListView` into the component.
- **Determine Current State:** Create a boolean to identify if the user is actively searching:
  ```javascript
  const isSearching = searchQuery.trim().length > 0 || activeCategories.length > 0 || sortBy !== 'default';
  ```
- **Conditional Rendering layout:**
  - **Pinned Top Navbar:** Place `<Sidebar {...sidebarProps} compact />` sticky at the top.
  - **Dynamic Body:**
    - If `!isSearching`: Render the standard discovery carousels (`<Section title="Deals Near Me"... />` etc). 
    - If `isSearching`: Render `<ListView deals={filteredDeals} onSelectDeal={onSelectDeal} userCoords={userCoords} />` in an overflow-y-auto block.

### 3. Cleanup Existing Linkage
- Remove the "See All" action elements (like the `onViewNearest` prop previously added) from the `<Section>` components in `HomeTab.jsx`. A user can now simply use the top filters locally.
- In `App.jsx`, ensure the Desktop layout view properly adapts so that clicking "Home" anchors the updated smart filtering.

### 4. Edge Cases to Account For
- **State Preservation:** Confirm that `searchQuery` and `activeCategories` maintained by `App.jsx` > `useFilters` won't abruptly reset if a user clicks deeply into a Deal Modal and closes it.
- **UX Scrolling:** Ensure the transition from carousels (Discovery) to `ListView` (Search) handles CSS overflow and scrolling smoothly without jumping layout elements negatively.
